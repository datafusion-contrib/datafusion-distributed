# Upgrading from 4.0.0 to 5.0.0

This guide covers the source and behavioural changes merged after the
`v4.0.0` tag.

## 1. Task routing is asynchronous and runs once per task

The stage-level `RouteTasksHandler` API has been replaced by the asynchronous,
per-task `RouteTaskHandler` API:

| 4.0 API                                      | 5.0 API                                     |
|----------------------------------------------|---------------------------------------------|
| `RouteTasksHandler`                          | `RouteTaskHandler`                          |
| `RouteTasksEvent`                            | `RouteTaskEvent`                            |
| `RouteTasksEventResponse`                    | `RouteTaskEventResponse`                    |
| `{with,set}_distributed_route_tasks_handler` | `{with,set}_distributed_route_task_handler` |

Previously, a handler ran once per stage and returned one worker URL for each
task:

```rust
fn route_tasks(
    event: RouteTasksEvent<'_>,
) -> Option<Result<RouteTasksEventResponse>> {
    let mut urls = event
        .task_ctx
        .session_config()
        .get_distributed_worker_resolver()
        .ok()?
        .get_urls()
        .ok()?;
    urls.truncate(event.task_count);
    Some(Ok(RouteTasksEventResponse::new(urls)))
}

let state = SessionStateBuilder::new()
    .with_distributed_route_tasks_handler(route_tasks)
    .build();
```

In 5.0, implement the async handler and select and dial one worker for the task
described by the event:

```rust
use async_trait::async_trait;
use datafusion::common::Result;
use datafusion_distributed::{
    DistributedExt, RouteTaskEvent, RouteTaskEventResponse, RouteTaskHandler,
};

struct MyRouteTaskHandler;

#[async_trait]
impl RouteTaskHandler for MyRouteTaskHandler {
    async fn handle(
        &self,
        event: RouteTaskEvent<'_>,
    ) -> Option<Result<RouteTaskEventResponse>> {
        let urls = match event.worker_resolver.get_urls() {
            Ok(urls) => urls,
            Err(error) => return Some(Err(error)),
        };
        if urls.is_empty() {
            return None;
        }

        let url = urls[event.task_key.task_number % urls.len()].clone();
        Some(event.dialer.dial(url).await)
    }
}

let state = SessionStateBuilder::new()
    .with_distributed_route_task_handler(MyRouteTaskHandler)
    .build();
```

`event.dialer.dial(url).await` is expected to be used inside the
`RouteTaskHandler` implementation, therefore a worker is only chosen if a  
coordinator-to-worker connection is currently established. Implementations can
choose to retry on other worker if the current one is not available.

## 2. `WorkerPlanRewriteHandler::rewrite_worker_plan` renamed to `handle` and is now async

`WorkerPlanRewriteHandler::rewrite_worker_plan` has been renamed to `handle` to
match other handlers and is now `async`, so implementations can perform setup work
that needs to make network or I/O calls before the plan is handed off for execution.
The trait name and `{with,set}_distributed_worker_plan_rewrite_handler` registration
methods are unchanged, and callback-style sync functions are still supported via an
auto impl adapter.

## 3. Task-count annotations use soft task-count estimates and exact requirements

Replace `TaskCountAnnotation::Desired(n)` with `TaskCountAnnotation::soft(n)` and
`DesiredTaskCountEventResponse::desired(n)` with `DesiredTaskCountEventResponse::soft(n)`.
Soft task-count estimates accept integers or fractional values. Use `annotation.as_usize()` to
resolve an annotation to a task count.

For nodes that must run in one task, replace `TaskCountAnnotation::Maximum(1)` with
`TaskCountAnnotation::exact(NonZeroUsize::MIN, 0.0)` and
`DesiredTaskCountEventResponse::maximum(1)` with
`DesiredTaskCountEventResponse::exactly_one()`.

An exact requirement must be satisfied; it is no longer an upper cap. For former
`Maximum(n)` uses where `n > 1`, use `max(NonZeroUsize::new(n).expect("n must be non-zero"), soft)`
to keep an upper cap on the task count, `soft(n)` for a flexible task-count estimate, or
`exact(NonZeroUsize::new(n).expect("n must be non-zero"), soft)` when exactly `n` tasks are required.
An exact count greater than the number of available workers now fails planning, while a maximum
greater than the number of available workers does not. `min` and `try_range` are also available
for lower bounds and ranges.

Annotations have private fields and must be constructed through their public methods.

```rust
use std::num::NonZeroUsize;

let flexible = TaskCountAnnotation::soft(0.25);
let exact = TaskCountAnnotation::exact(NonZeroUsize::new(2).unwrap(), 0.25);
let response = DesiredTaskCountEventResponse::exact(NonZeroUsize::new(2).unwrap(), 0.25);
```

## 4. Align direct iceberg-rust dependencies

`datafusion-distributed-iceberg` now uses iceberg-rust revision
`5b82ab99aeaf50bf4f5b3b776ac9cd6380a5f3e3`. If your application pins
`iceberg` or `iceberg-storage-opendal` directly and passes its `Table`, `Runtime`,
or `StorageFactory` to this crate, update those dependencies to the same revision.
Alternatively, use `datafusion_distributed_iceberg::iceberg` for the Iceberg
types you pass to its public APIs.

## 5. Assigned Iceberg scans

When eager planning is enabled, downcast a `DataSourceExec`'s source to
`EagerIcebergDataSource`. Use `planned_files()` to iterate its assigned files
or `planned_partition_tasks(partition)` to inspect one local partition. These
borrowed accessors do not return `Option`: an assigned source always has files,
possibly an empty collection.

Lazy scans use `LazyIcebergDataSource` and its concrete `feed()` accessor.
Rename imports and references from `IcebergDataSource` to `LazyIcebergDataSource`
and from `IcebergCodec` to `LazyIcebergCodec`. The old names are no longer exported.
Update custom work-unit feed registrations to use `map(LazyIcebergDataSource::feed)`.

`set_iceberg_integration` registers both `LazyIcebergCodec` for lazy scans and
`EagerIcebergCodec` for eager scans. If you register codecs manually, register
both in the same order on coordinators and workers before enabling eager
planning. The lazy scan payload is unchanged. Codec dispatch uses registration
positions, so deploy matching codec registrations across the cluster.

## 6. Iceberg integration options

When constructing `IcebergIntegrationOptions` with an explicit struct literal,
add `file_io_codec: None` to retain the default storage encoding, or provide
`Some(Arc::new(codec))` to customize it. Literals using `..Default::default()`
need no changes.
